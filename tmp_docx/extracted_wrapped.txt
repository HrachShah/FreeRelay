determined, the profiler computes a confidence score (0.0–1.0) representing how reliable the profile is. Low confidence
triggers conservative routing (prefer proven providers over exploration).def compute_confidence(profile:
WorkloadProfile, classifier_proba: float) -> float:    score = classifier_proba                        # task_family
classifier confidence (0.5–1.0)    if profile.has_images and not profile.context_topology == 'multimodal':        score
*= 0.8                               # topology mismatch → lower confidence    if profile.tool_count > 5:        score
*= 0.9                               # complex tool graphs → profiler less reliable    if
profile.prompt_tokens_estimated > 64000:        score *= 0.85                              # very long context → harder

context drift    return max(0.3, min(1.0, score))               # floor at 0.3 — never route blind⚑  When confidence <

pair receives a score. The pair with the highest score is selected. 'Available' means: circuit state is CLOSED or
HALF_OPEN, AND budget_score > 0, AND tenant policy score is 1.0.def expected_utility(    provider: str, model: str,
profile: WorkloadProfile,    registry: CapabilityRegistry,    bandit: BanditState,    budget: BudgetState,    circuit:
CircuitState,    policy: TenantPolicy,) -> float:    cap = registry.get(provider, model)    arm =
bandit.get_arm(provider, model, profile.task_family)    # Term 1: P(success) — learned from outcome records    p_success
= arm.mean_quality if arm.n_pulls >= 10 else cap.prior_quality    # Term 2: Quality estimate — EWMA of judge scores for
this (provider, task_family)    quality = arm.ewma_quality    # Term 3: Schema success probability — from capability
registry    schema_prob = cap.schema_compliance_rate.get(profile.output_contract, 0.5)    if profile.output_contract ==
'prose':        schema_prob = 1.0                        # no schema to fail    # Term 4: Latency utility — maps p95
TTFT to [0, 1] given latency class    latency_budget = {'interactive': 500, 'async_': 3000, 'batch':
30000}[profile.latency_class]    latency_utility = 1.0 / (1.0 + cap.p95_ttft_ms / latency_budget)    # Term 5: Cost
utility — normalized against tenant cost ceiling    max_cost = policy.cost_ceiling_per_request_usd or 0.01    est_cost =
(profile.prompt_tokens_estimated * cap.cost_per_prompt_token +                profile.prompt_tokens_estimated * 0.5 *
cap.cost_per_completion_token)    cost_utility = 1.0 - min(1.0, est_cost / max_cost)    # Term 6: Safety utility —
binary gate    safety_utility = 1.0 if cap.safety_tier >= policy.min_safety_tier else 0.0    # Term 7: Tenant policy
weight — binary gate    tenant_weight = 1.0 if provider in policy.allowed_providers else 0.0    # Term 8: Circuit score
circuit_score = {'CLOSED': 1.0, 'HALF_OPEN': 0.5, 'OPEN': 0.0}[circuit.state]    # Term 9: Budget score — square root to
reduce penalty for partial exhaustion    budget_score = math.sqrt(budget.remaining_ratio)    # Term 10: UCB exploration
bonus    N = bandit.total_pulls    n_i = max(1, arm.n_pulls)    ucb_bonus = math.sqrt(2 * math.log(max(2, N)) / n_i) *
0.1   # scaled to utility range    # Economic policy modulates quality/cost tradeoff    econ = {'cheapest': (0.4, 1.6),
'balanced': (1.0, 1.0), 'best': (1.6, 0.4)}    q_weight, c_weight = econ[profile.economic_policy]    utility = (
(p_success * quality ** q_weight * schema_prob)        * (latency_utility * cost_utility ** c_weight)        *
safety_utility * tenant_weight        * circuit_score * budget_score        + ucb_bonus * profile.profiler_confidence
)    return utility5.2 UCB Bandit — Full State MachineThe bandit maintains one arm per (provider, model, task_family)
triple. State is stored in Redis and updated by the control plane on a 60-second tick after consuming outcome records.#
Arm update — runs in control plane on 60s tickdef update_arm(arm: BanditArm, outcome: OutcomeRecord) -> BanditArm:    #
Quality signal: composite of validation, judge, and proxy signals    quality_signal = (        0.4 *
float(outcome.output_valid)        + 0.3 * (outcome.judge_score or estimate_judge_score(outcome))        + 0.15 *
float(not outcome.repair_triggered)        + 0.1  * float(not outcome.client_retried)        + 0.05 * float(not
outcome.client_regenerated)    )    # EWMA update — alpha = 0.1 for stability, higher for recent bias    alpha = 0.1 if
arm.n_pulls > 100 else 0.3    arm.ewma_quality = alpha * quality_signal + (1 - alpha) * arm.ewma_quality    #
Incremental mean (Welford's online algorithm — numerically stable)    arm.n_pulls += 1    delta = quality_signal -
arm.mean_quality    arm.mean_quality += delta / arm.n_pulls    arm.m2 += delta * (quality_signal - arm.mean_quality)  #
for variance    arm.variance = arm.m2 / arm.n_pulls if arm.n_pulls > 1 else 0.0    arm.last_updated_ts = time.time()
return armdef estimate_judge_score(outcome: OutcomeRecord) -> float:    # When judge hasn't run yet, estimate from
structural signals    score = 0.5    if outcome.schema_passed: score += 0.2    if not outcome.repair_triggered: score +=
0.15    if not outcome.hallucination_flags: score += 0.15    return min(1.0, score)5.3 Routing Policy DSL v2 — Full

Engine ArchitectureThe DAG engine is an async Python runtime that executes directed acyclic graphs of inference steps.
It is the core of what makes FreeRelay an orchestration platform rather than a gateway. The engine is deterministic:
given the same workflow definition and the same model outputs, it always produces the same execution trace.Step graph is
parsed from YAML at startup and compiled into a Python dependency graph (dict[step_id, set[dependency_ids]]).At
execution time, steps with no unresolved dependencies are dispatched immediately via asyncio.create_task.As steps
complete, dependent steps are unblocked and dispatched. This is a topological traversal with async concurrency at each
frontier.Step outputs are stored in an ExecutionContext dict, keyed by step_id. Downstream steps read their inputs from
this context.Conditional steps evaluate their condition against the context before executing. If condition is false,
step is skipped and marked as skipped in the trace.The engine enforces a global DAG timeout. If any step exceeds its
per-step timeout, it is cancelled and the fallback strategy executes.Every step execution is recorded in the
ExecutionTrace, which is attached to the OutcomeRecord for full provenance.6.2 All 11 Execution Strategies — Complete
Implementation SpecsStrategy 1: singleRoute to one provider using expected utility. The default strategy for all non-
orchestrated requests.async def single(step: Step, ctx: ExecutionContext, router: Router) -> StepOutput:    provider,
model = router.select(ctx.profile, step.model_pool, step.constraints)    response = await provider.complete(ctx.request,
model)    return StepOutput(provider=provider.name, model=model, response=response)Strategy 2: fanoutFire to N providers
in parallel. Collect all responses. Feed all N responses to the next step (typically a judge or verifier).async def
fanout(step: Step, ctx: ExecutionContext, router: Router) -> StepOutput:    n = step.candidates  # typically 2–5
providers = router.select_top_n(ctx.profile, step.model_pool, n)    tasks = [asyncio.create_task(p.complete(ctx.request,
m)) for p, m in providers]    results = await asyncio.gather(*tasks, return_exceptions=True)    # Filter out exceptions,
keep successful responses    candidates = [r for r in results if not isinstance(r, Exception)]    if not candidates:
raise AllProvidersFailedError(step.id)    return StepOutput(candidates=candidates)  # list output feeds
judge/verifierStrategy 3: judgeA judge model receives N candidate responses and selects the best one based on a rubric,
or produces a quality score for each. The judge model is chosen from a separate model pool (typically a strong reasoning
model).async def judge(step: Step, ctx: ExecutionContext, router: Router) -> StepOutput:    candidates =
ctx.get_output(step.input_step).candidates    judge_prompt = build_judge_prompt(ctx.request, candidates, step.rubric)
judge_provider, judge_model = router.select(ctx.profile, step.model_pool, step.constraints)    judgment = await
judge_provider.complete(judge_prompt, judge_model)    best_idx = parse_judge_selection(judgment)  # expects JSON:
{selected: int, scores: [float]]}    winner = candidates[best_idx]    winner.provenance.judge_scores =
parse_judge_scores(judgment)    winner.provenance.judge_model = judge_model    return StepOutput(response=winner,
judgment=judgment)Strategy 4: verifierA verifier model checks a response for factual consistency, groundedness, policy
compliance, or other domain-specific correctness. Returns a pass/fail verdict with a reason.Strategy 5: repairTriggered
when a prior step's output fails validation. The repair model receives the original prompt, the failed response, and the
specific validation failure reason. It attempts to produce a corrected response.async def repair(step: Step, ctx:
ExecutionContext, router: Router) -> StepOutput:    failed_output = ctx.get_output(step.input_step)    failures =
ctx.get_validation_result(step.input_step).failures    repair_prompt = build_repair_prompt(
original_request=ctx.request,        failed_response=failed_output.response,        failures=failures,
constraints=step.constraints,  # e.g. temperature=0.1, force_json=True    )    # Prefer provider with highest
schema_compliance_rate for this output_contract    provider, model = router.select_for_repair(ctx.profile,
step.model_pool)    repaired = await provider.complete(repair_prompt, model)    return StepOutput(response=repaired,
repair_attempt=True)Strategy 6: cheap_first_escalateasync def cheap_first_escalate(step: Step, ctx: ExecutionContext,
router: Router) -> StepOutput:    # Tier 1: cheapest eligible provider    cheap_provider, cheap_model =
router.select_cheapest(ctx.profile, step.model_pool)    response = await cheap_provider.complete(ctx.request,
cheap_model)    score = await fast_quality_score(response, ctx.profile)  # heuristic only, < 5ms    if score >=
step.escalation_threshold:  # typically 0.75        return StepOutput(response=response, escalated=False)    # Tier 2:
strongest eligible provider    strong_provider, strong_model = router.select_strongest(ctx.profile, step.model_pool)
strong_response = await strong_provider.complete(ctx.request, strong_model)    return
StepOutput(response=strong_response, escalated=True, cheap_score=score)Strategy 7: consensusasync def consensus(step:
Step, ctx: ExecutionContext, router: Router) -> StepOutput:    n = step.candidates  # typically 3    providers =
router.select_diverse(ctx.profile, step.model_pool, n)  # maximize provider diversity    responses = await
asyncio.gather(*[p.complete(ctx.request, m) for p, m in providers])    agreement_matrix =
compute_pairwise_similarity(responses)  # cosine sim on response embeddings    best_pair =
find_highest_agreement_pair(agreement_matrix)    if best_pair.similarity >= step.min_agreement:  # typically 0.80
return StepOutput(response=best_pair.responses[0], consensus_reached=True, agreement=best_pair.similarity)    # No
consensus — fall back to judge strategy    return await judge(step, ctx.with_candidates(responses), router)Strategy 8:
hedgeasync def hedge(step: Step, ctx: ExecutionContext, router: Router) -> StepOutput:    top2 =
router.select_top_n(ctx.profile, step.model_pool, 2)    tasks = {asyncio.create_task(p.complete(ctx.request, m)): (p, m)
for p, m in top2}    done, pending = await asyncio.wait(tasks.keys(), return_when=asyncio.FIRST_COMPLETED)    for task

Anomaly Detection — EWMA Control LimitsThe anomaly detector runs in the control plane on a 5-minute tick. It computes
EWMA of each latency and quality metric and flags anomalies using 3-sigma control limits. When an anomaly is detected,
it immediately sets the appropriate degradation flag in the capability registry and triggers a spot benchmark run.def
detect_anomaly(metric_series: list[float], new_value: float,                   alpha: float = 0.2) -> AnomalyResult:
# EWMA    ewma = metric_series[-1] if metric_series else new_value    ewma = alpha * new_value + (1 - alpha) * ewma    #
EWMA variance (for control limits)    ewma_var = alpha * (new_value - ewma)**2 + (1 - alpha) * (metric_series[-2] if
len(metric_series) > 1 else 0)    sigma = math.sqrt(ewma_var)    upper_control_limit = ewma + 3 * sigma
lower_control_limit = ewma - 3 * sigma    is_anomaly = new_value > upper_control_limit or new_value <
lower_control_limit    severity = abs(new_value - ewma) / sigma if sigma > 0 else 0    return
AnomalyResult(is_anomaly=is_anomaly, severity=severity, ewma=ewma, sigma=sigma)11. Resilience Engineering11.1 Circuit

fundamental metric is not cost-per-request. It is cost-per-correct-output. A provider that costs $0.001 per request but
requires 2.3 repair attempts costs more than a provider at $0.002 with a 0.97 first-try success rate. The expected cost
formula:def expected_cost_per_success(provider: str, model: str, profile: WorkloadProfile,
cap: CapabilityRecord, bandit: BanditArm) -> float:    base_cost = (profile.prompt_tokens_estimated *
cap.cost_per_prompt_token +                 profile.prompt_tokens_estimated * 0.5 * cap.cost_per_completion_token)
p_first_try_success = bandit.mean_quality * cap.schema_compliance_rate.get(        profile.output_contract, 0.8)    #
Expected number of attempts: geometric distribution    expected_attempts = 1 / max(0.1, p_first_try_success)    # Each
repair attempt costs ~40% of original (shorter prompt, same completion)    total_expected_cost = base_cost * (1 + 0.4 *
(expected_attempts - 1))    return total_expected_cost12.2 EWMA Budget Forecaster# Runs in control plane on 1-minute
